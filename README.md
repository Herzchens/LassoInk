# LassoInk Capture Diagnostic and Minimal Canvas

## Implemented scope

The M1 diagnostic is a standalone Windows Winit application. The default `direct` mode copies direct `GetPointerPenInfoHistory` records inside Winit's `WM_POINTER` message hook, then returns `false` so Winit continues dispatch. It also records Winit `Touch`, cursor, mouse-button, focus, and device add/remove events as separately tagged public/application streams. Use `--capture-mode wintab` to explicitly select the Wintab driver path. Wintab failure is reported; it does not switch to direct WM_POINTER. Public Winit events continue as their own comparison stream and are never treated as a Wintab fallback.

Public Winit events retain Winit's device ID and force representation as public event data, separate from native `sourceDevice`, pointer ID, and HWND values. They have no native timestamp or CT430 tilt. At most one Touch event per dispatch receives a message association, and only when the current hooked message, Winit window HWND, and `Touch.id` match. Pen classification is separate: only `GetPointerType == PT_PEN` yields `ConfirmedPen`; a known non-pen type is `ConfirmedNonPen`, while an unavailable or failed type query stays unclassified even if the message association is known. Additional frame events, unmatched events, and reentrant/ambiguous events have no association and remain unclassified. The association identifies the dispatch message only; it does not join individual Winit frame events to direct history samples.

Wintab is loaded only from an absolute path under the Windows System32 directory using restricted loader flags. The DLL and SDK binaries are not bundled. The probe requests a fixed packet mask and absolute context mode; it records the actual packet mask, mode, queue size, `lcDevice`, cursor and context values. `pkTime` remains raw in the configured absolute-system-time or relative-milliseconds domain, separate from QPC and app arrival time. Queued packets are drained on both `WT_PACKET` and `WT_PROXIMITY`; every proximity enter/leave is logged with raw `MSG` fields, raw `lParam` flags, `MSG.time`, and app arrival even when the queue is empty. A per-window subclass is installed before `WTOpen` so sent and posted Wintab context controls are recorded once with raw HWND/message parameters and app-arrival time; sent controls have no Winit MSG timestamp. The queued hook ignores those control IDs and checks a nonblocking pending-control signal before reading Wintab packets. It rechecks that signal after each native queue query and packet read; a control observed during a packet read stops the drain and marks any rows returned by that call as uncertain raw diagnostics, excluded from uninterrupted Wintab metrics. The safe Winit callback drains WTOpen's initial control messages before packet processing and clears the signal only when the queue is empty and context state remains valid. The subclass forwards messages to Winit; its 128-entry pending queue reports overflow or callback failure. State changes and driver calls run at a later Winit callback boundary. If a requested queue size fails, the probe retries smaller sizes down through one packet; it records the actual capacity and reports a reduced accepted capacity as partial status without inferring sample loss. Context/device changes, overlap changes, overflow flags, serial discontinuities, and bounded-drain issues are also reported as partial status. Capture stops and requests context close at the next Winit loop boundary after a shared storage cap or context/order change; there is no same-session reopen. A first self-context overlap notification before any packet is treated as WTOpen's initial top-of-order setup only when raw status has `CXS_ONTOP` and neither `CXS_DISABLED` nor `CXS_OBSCURED`; adverse status, later overlap changes, or foreign-context overlap stop the Wintab stream. If `WTClose` fails at a stop boundary, the probe tries `WTEnable(FALSE)` to stop packet processing and records the pre-disable queue count when available. If both operations fail, the failure remains visible and the DLL stays loaded while the HCTX may remain live.

Raw input records are streamed to a versioned local TSV session (`LASSOINK-SESSION`, schema 2) at Winit callback boundaries. Output defaults to the ignored `local_capture/` directory; use `--session-dir` or `--session-path` to select another local path. Final publication uses a same-directory no-clobber Win32 move. If the destination already exists or finalization fails, its bytes are preserved and the new session remains recoverable as `.partial`. The writer counts every row and reserves its CPU and END rows against the parser line cap, so it never finalizes a session that its parser rejects for line count. The parser also reads schema 1 sessions. It applies fixed file, line, sample, record, metadata, partition, and duplicate-fingerprint limits, and rejects malformed schemas and oversized rows instead of reading them into unbounded buffers.

The source-agnostic project journal is separate from the M1 diagnostic TSV and does not promote M1 candidate streams. Schema 3 preserves each physical sample's source API/device/pointer/stroke/journal/session identity, source sequence, raw payload and units, native clock domain/count/frequency, application arrival epoch, contact/range state, nullable structured button state, and nullable tilt/rotation. The direct adapter leaves structured pen-button state null because it has not adopted a supported mapping. Its opaque `DWP3` payload retains `dwKeyStates` and `penFlags` separately; `dwKeyStates` are keyboard modifier state, not pen buttons. Session/device/configuration metadata is append-only with declaration/source provenance. Every resumed process begins a new session/arrival-clock epoch; old sample identities and elapsed times remain unchanged. Logical targets include journal and session IDs, so matching device/pointer/stroke labels in different epochs cannot merge. Journal-local legacy tombstone/move/correction events remain readable and schema 1/2 migration preserves validated raw rows and the prior logical view while appending migration provenance; storage identity is preserved and schema 1/2 journals cannot be appended directly. New erasure, restore, move, and correction actions are single bounded journal rows; undo and redo append control rows referencing prior actions. A multi-stroke edit must fit the bounded single-row target cap or it is rejected before write, so a crash cannot expose only part of that logical action. Raw physical samples are never rewritten by edits. Journal parsing is bounded: a torn final line is recoverable, while a complete malformed record errors rather than being skipped. Writers hold an exclusive OS file lease for their lifetime; append recovery validates, truncates a torn final record if needed, and resumes through the same leased handle. Every accepted append is synchronized before in-memory state advances; after a write/sync error the writer is poisoned and callers must reopen/replay. `sync_data` runs per row, so capture integration needs explicit backpressure and stop behavior. Snapshots bind to journal identity, a validated byte prefix, event sequence, logical revision, session epochs and edit state using FNV-1a consistency fingerprints (not authentication). Missing, stale, corrupt, wrong-journal, wrong-prefix/revision, or mismatched-state snapshots fall back to canonical replay. `load_with_snapshot` currently validates the full canonical journal before applying snapshot-plus-tail, so it does not accelerate startup.

The journal v3/session and edit semantics currently use deterministic software fixtures. They preserve session epochs without selecting or merging a capture source and do not establish CT430 fidelity.

## M3 minimal canvas

The current M3 canvas renders committed, journal-projected direct `WM_POINTER` pen strokes using GDI. That adapter remains explicitly provisional. `--capture-mode wintab` continues to record diagnostics but does not draw through Wintab, and no source falls back to mouse drawing. New direct strokes append `StrokeStarted`, immutable raw sample rows, then a visibility commit only after a native `WM_POINTERUP`. Leave, capture loss, focus loss, device change, contact loss without an observed up, or shutdown appends an interruption; raw rows remain in the project journal and the incomplete stroke is not rendered as a completed stroke.

Project capture and edits go through a bounded worker queue. Each accepted journal append is synchronized before the UI receives its durable acknowledgement. Queue saturation stops further input, retains one pending batch for retry, and reports incomplete state; if shutdown cannot enqueue that batch, the project-finalization record reports its omitted event and sample counts. The project journal remains append-only and is stored under ignored `local_capture/` by default. `--project-path PATH` creates a project, while `--open-project PATH` appends a fresh session/arrival-clock epoch to an existing schema-v3 project. Legacy schema-1/2 inputs are migrated to a sibling schema-v3 file without rewriting the selected source.

The canvas shows pending strokes before the writer acknowledgement, keeps the preview while one bounded batch is pending, promotes it only after the durable visibility commit, and removes it on interruption or write failure. Each typed stroke-start row stores the observed `ClientToScreen` client origin and the DPI, pan, zoom, and toolbar frame for that stroke. Replay maps unchanged raw screen-pixel positions through the captured per-stroke frame, not the current window location. Window movement, DPI changes, and pan/zoom changes interrupt active contact; another stroke requires a fresh native down after lift.

Canvas controls: F1 selects the provisional pen tool; mouse drawing remains disabled. F2 selects the eraser; direct PT_PEN contact erases hit strokes on a proven native up, while mouse users click a rendered stroke and press Delete. F3 selects; pen or mouse can select existing strokes, then drag one selected stroke or use an arrow key to append a move. Direct eraser/select observations stay as raw physical rows without creating visible strokes. Ctrl+Z and Ctrl+Y append undo/redo controls; F5/F6 provide the same actions. Use the wheel to zoom and middle/right drag to pan. F4 or Enter shows that Convert has no configured provider. These controls edit logical journal state; they never rewrite physical sample rows.

M4 defines a versioned JSON process protocol for capability discovery and recognition requests/results, carried over bounded local standard-input/output frames. Requests retain the exact journal boundary, region/line, language hints, source-ordered session-scoped StrokeRefs, raw units, and per-stroke view frames. Each request explicitly declares the required input modalities and each result echoes the modalities consumed; stroke samples remain canonical provenance for raster-only calls. Raster payloads are bounded opaque bytes with declared dimensions, not decoded pixels. The input-view ID covers the shared selected input and captured view, including modality choice, and is independent of provider configuration; configuration has a separate fingerprint echoed by handshake/results. Raw sample positions remain separate from projected positions after logical edits. Handshake, request, result, and stderr sizes are capped; worker I/O and shutdown have deadlines. Windows provider launch uses an atomic Job Object assignment with kill-on-close and explicit stdio-handle inheritance on Windows 10 or newer; setup failures stop the request without uncontained fallback. A crash, timeout, or stale result returns an error without dropping ink or switching providers. Result scores remain provider-native and uncalibrated. Starting a worker requires an explicit operator-approved absolute executable/configuration, separate from project metadata. The core has zero configured providers by default, no provider executable is shipped, and Convert remains unavailable. The CI mock worker is test-only.

After the direct provider exits, the runner releases its process handle and retains the Job Object while querying `ActiveProcesses`, reissuing termination while the count is positive. It joins the stdio helpers before closing the job; query, termination, or deadline failures retain resources in the bounded poisoned cleanup registry and block further provider work until the tree is reaped.

In-memory pending records are bounded by the existing 4,096-record and 131,072-native-sample caps. A direct native history is capped at 65,536 samples; one Wintab message drain is capped at 4,096 packets. When any capture or session-output limit is reached, capture stops and the window reports incomplete state. Invalid direct rows remain in the raw session, while valid-direct-pen row counts and pressure/interval metrics require `PT_PEN`, matching requested pointer ID, a reported pressure mask, and pressure in the inclusive 0 through 1024 range. Validation anomaly counts are separate from raw row counts. Wintab rows interrupted by a control notification, context/queue quality issue, or invalid packet status stay raw and are excluded from confident Wintab pressure metrics. Raw overlaps and duplicate fingerprints are retained; no sample rows are removed. Repeated direct fingerprints are counted but skipped in direct QPC interval and pressure distributions with an explicit exclusion reason.

`POINTER_INFO.PerformanceCount` and a QPC observation sampled at the Win32 hook boundary use the same QPC count domain, so the report may compute a message-receipt-to-hook-observation age and raw QPC intervals when frequency and values are available. P50/P95/P99 use the discrete nearest-rank rule `ceil(n*p/100)` within each qualified partition, with rank 1 as the minimum. These are not physical sensing-to-display latency measures. `dwTime`, Wintab `pkTime` (with mode), Winit public timestamps, and app `Instant` arrival remain separate. Missing/negative QPC values are reported as null with a reason. Derived metrics are partitioned by API, device, pointer, observed stroke, native clock, and pressure representation. Direct pressure histograms and entropy use valid unique raw pressure values only; repeat-run summaries are limited to valid unique direct rows within an observed stroke. Public Winit Force remains its own exact representation, partitioned by the recorded pen-classification state. Wintab `NORMAL_PRESSURE` remains uncalibrated raw u32 with unknown driver range and is never normalized or compared with direct pressure. No 220 Hz threshold or automatic frame-lock conclusion is applied. Focus loss, device lifecycle, pointer enter/re-entry/leave/capture loss, and device-range changes invalidate affected active stroke buckets; missing boundaries stay unclassified. The report never bridges clocks or strokes, joins public events to individual direct samples, interprets `frameId` gaps as proven loss, or claims hardware fidelity.

Process CPU is sampled with `GetProcessTimes` at app-arrival boundaries. Raw user/kernel FILETIME words and the measurement interval are retained. Its core-equivalent ratio covers the whole process and all its threads, includes the event loop and local session I/O, can exceed 100%, and is not an isolated capture-thread or driver cost. Positional jitter is unresolved because this probe has no calibrated noise measurement. Physical end-to-end latency is unresolved because there is no trusted clock bridge to an instrumented display endpoint.

The timeline includes direct pointer enter/leave/capture/device messages; Wintab packet/proximity and control/error messages; Winit focus and input-device add/remove; and event-loop wake delays over the declared diagnostic threshold. `--controlled-stall-ms N` arms a one-shot pause; press F9 once after the capture window is running to record app-arrival start/end markers and measured duration around a deliberate UI-thread pause (1..30000 ms). It never pauses automatically during startup and synthesizes no samples. Windows Ink, tablet profile, driver version, active area, display mapping, and pressure curve are owner declarations. The explicitly requested `--capture-mode direct|wintab` is independent of Windows Ink; the owner runner reads the Windows build from the current-version registry and records its source. The tool does not change system or driver settings. Live title refreshes remain limited to once per second.

In direct mode, the window reports `CAPTURE UNAVAILABLE` if the required Win32 pointer APIs cannot be loaded. A missing QPC frequency appears as a timing warning and does not prevent position capture.

Gate 0 hardware status remains **DEFERRED / NOT PASSED** until real CT430 measurements are reviewed. The M1 capture comparison remains diagnostic and does not select a canonical capture source. Hardware-independent M2 journal and replay work may proceed using software fixtures; those fixtures prove only the software behavior exercised, not CT430 fidelity or an adapter choice.

## Requirements and build

The project pins Rust 1.100.0 for `x86_64-pc-windows-msvc`. Install the pinned toolchain and target if they are not already present:

```powershell
rustup toolchain install 1.100.0 --profile minimal --component clippy --component rustfmt --target x86_64-pc-windows-msvc
```

Run the diagnostic or parse a finalized/partial session:

```powershell
cargo run
cargo run -- --capture-mode direct
cargo run -- --capture-mode wintab
cargo run -- --capture-mode direct --session-dir local_capture --trial-id ink-off-direct --windows-ink off --tablet-profile default
cargo run -- --capture-mode wintab --session-path local_capture\ink-off-wintab-osu.tsv --windows-ink off --tablet-profile osu
cargo run -- --controlled-stall-ms 2000 --capture-mode direct --trial-id controlled-stall
cargo run -- --report local_capture\session-file.tsv
cargo run -- --status
cargo run -- --version
cargo run -- --help
```

`--capture-mode` must be selected independently of `--windows-ink`. If the controlled stall is requested, press F9 once after the window is running; a configured duration alone never causes a startup pause.

The quality checks used by Windows CI are:

```powershell
cargo +1.100.0 fmt --all -- --check
cargo +1.100.0 clippy --locked --workspace --all-targets -- -D warnings
cargo +1.100.0 test --locked --workspace
cargo +1.100.0 build --locked --workspace
```

The default local test suite excludes native HWND, Winit event-loop, and GDI integration tests. They run only in a separate guarded GitHub-hosted Windows CI job after the default checks. The native tests require explicit opt-in, the GitHub-hosted Windows runner marker, and the `Herzchens/LassoInk` repository identity before they can call UI APIs.

## Data handling

M1 session files may contain sensitive handwriting, timing, pressure, and device data. Keep them in an ignored local path or the owner-selected local session directory. They are not uploaded. Do not put them in the owner package, Git, or a public issue. The owner runner defaults session files to `%LOCALAPPDATA%\LassoInk\capture-sessions`, outside the package directory.

## Dependencies

The app directly depends on Serde 1.0.229 with derives, Serde JSON 1.0.154 for the bounded local provider protocol, Winit 0.30.13 with default features disabled and the `rwh_06` interoperability feature, plus Windows-target `windows-sys` 0.52.0. `Cargo.lock` records the resolved transitive packages including `raw-window-handle`.
