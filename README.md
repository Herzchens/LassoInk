# LassoInk Capture Diagnostic and Minimal Canvas

## Implemented scope

The M1 diagnostic is a standalone Windows Winit application. The default `direct` mode copies `GetPointerPenInfoHistory` records inside Winit's `WM_POINTER` message hook, then returns `false` so Winit continues dispatch. It also records Winit `Touch`, cursor, mouse-button, focus, and device add/remove events as separately tagged public/application streams. The canonical capture contract is owner-locked to Direct WM_POINTER with Windows Ink ON for the tested setup. `--capture-mode` and `--windows-ink` are independent declarations. In the owner-tested Ink OFF state, Direct `PT_PEN` history disappeared into separately tagged public mouse events; public mouse events are never promoted to ink. `--capture-mode wintab` remains an explicit diagnostic path; it produced no usable packet/proximity stream in the owner-tested environment and is not a viable fallback there. Public Winit events remain diagnostic comparison data only and are never a capture fallback. Diagnostic runs in other environments do not automatically requalify or change the owner-locked capture contract.

Public Winit events retain Winit's device ID and force representation as public event data, separate from native `sourceDevice`, pointer ID, and HWND values. They have no native timestamp or CT430 tilt. At most one Touch event per dispatch receives a message association, and only when the current hooked message, Winit window HWND, and `Touch.id` match. Pen classification is separate: only `GetPointerType == PT_PEN` yields `ConfirmedPen`; a known non-pen type is `ConfirmedNonPen`, while an unavailable or failed type query stays unclassified even if the message association is known. Additional frame events, unmatched events, and reentrant/ambiguous events have no association and remain unclassified. The association identifies the dispatch message only; it does not join individual Winit frame events to direct history samples.

Wintab is loaded only from an absolute path under the Windows System32 directory using restricted loader flags. The DLL and SDK binaries are not bundled. The probe requests a fixed packet mask and absolute context mode; it records the actual packet mask, mode, queue size, `lcDevice`, cursor and context values. `pkTime` remains raw in the configured absolute-system-time or relative-milliseconds domain, separate from QPC and app arrival time. Queued packets are drained on both `WT_PACKET` and `WT_PROXIMITY`; every proximity enter/leave is logged with raw `MSG` fields, raw `lParam` flags, `MSG.time`, and app arrival even when the queue is empty. A per-window subclass is installed before `WTOpen` so sent and posted Wintab context controls are recorded once with raw HWND/message parameters and app-arrival time; sent controls have no Winit MSG timestamp. The queued hook ignores those control IDs and checks a nonblocking pending-control signal before reading Wintab packets. It rechecks that signal after each native queue query and packet read; a control observed during a packet read stops the drain and marks any rows returned by that call as uncertain raw diagnostics, excluded from uninterrupted Wintab metrics. The safe Winit callback drains WTOpen's initial control messages before packet processing and clears the signal only when the queue is empty and context state remains valid. The subclass forwards messages to Winit; its 128-entry pending queue reports overflow or callback failure. State changes and driver calls run at a later Winit callback boundary. If a requested queue size fails, the probe retries smaller sizes down through one packet; it records the actual capacity and reports a reduced accepted capacity as partial status without inferring sample loss. Context/device changes, overlap changes, overflow flags, serial discontinuities, and bounded-drain issues are also reported as partial status. Capture stops and requests context close at the next Winit loop boundary after a shared storage cap or context/order change; there is no same-session reopen. A first self-context overlap notification before any packet is treated as WTOpen's initial top-of-order setup only when raw status has `CXS_ONTOP` and neither `CXS_DISABLED` nor `CXS_OBSCURED`; adverse status, later overlap changes, or foreign-context overlap stop the Wintab stream. If `WTClose` fails at a stop boundary, the probe tries `WTEnable(FALSE)` to stop packet processing and records the pre-disable queue count when available. If both operations fail, the failure remains visible and the DLL stays loaded while the HCTX may remain live.

Raw input records are streamed to a versioned local TSV session (`LASSOINK-SESSION`, schema 2) at Winit callback boundaries. Output defaults to the ignored `local_capture/` directory; use `--session-dir` or `--session-path` to select another local path. Final publication uses a same-directory no-clobber Win32 move. If the destination already exists or finalization fails, its bytes are preserved and the new session remains recoverable as `.partial`. The writer counts every row and reserves its CPU and END rows against the parser line cap, so it never finalizes a session that its parser rejects for line count. The parser also reads schema 1 sessions. It applies fixed file, line, sample, record, metadata, partition, and duplicate-fingerprint limits, and rejects malformed schemas and oversized rows instead of reading them into unbounded buffers.

The source-agnostic project journal is separate from the M1 diagnostic TSV and does not promote M1 candidate streams. Schema 3 preserves each physical sample's source API/device/pointer/stroke/journal/session identity, source sequence, raw payload and units, native clock domain/count/frequency, application arrival epoch, contact/range state, nullable structured button state, and nullable tilt/rotation. The direct adapter leaves structured pen-button state null because it has not adopted a supported mapping. Its opaque `DWP3` payload retains `dwKeyStates` and `penFlags` separately; `dwKeyStates` are keyboard modifier state, not pen buttons. Raw native pen-mask and tilt/rotation slots, including raw zeroes, remain in opaque sample data for forensics. CT430 semantic tilt/rotation remains unavailable/null regardless of raw pen-mask bits or zero slots. Session/device/configuration metadata is append-only with declaration/source provenance. Every resumed process begins a new session/arrival-clock epoch; old sample identities and elapsed times remain unchanged. Logical targets include journal and session IDs, so matching device/pointer/stroke labels in different epochs cannot merge. Journal-local legacy tombstone/move/correction events remain readable and schema 1/2 migration preserves validated raw rows and the prior logical view while appending migration provenance; storage identity is preserved and schema 1/2 journals cannot be appended directly. New erasure, restore, move, and correction actions are single bounded journal rows; undo and redo append control rows referencing prior actions. A multi-stroke edit must fit the bounded single-row target cap or it is rejected before write, so a crash cannot expose only part of that logical action. Raw physical samples are never rewritten by edits. Journal parsing is bounded: a torn final line is recoverable, while a complete malformed record errors rather than being skipped. Writers hold an exclusive OS file lease for their lifetime; append recovery validates, truncates a torn final record if needed, and resumes through the same leased handle. Every accepted append is synchronized before in-memory state advances; after a write/sync error the writer is poisoned and callers must reopen/replay. `sync_data` runs per row, so capture integration needs explicit backpressure and stop behavior. Snapshots bind to journal identity, a validated byte prefix, event sequence, logical revision, session epochs and edit state using FNV-1a consistency fingerprints (not authentication). Missing, stale, corrupt, wrong-journal, wrong-prefix/revision, or mismatched-state snapshots fall back to canonical replay. `load_with_snapshot` currently validates the full canonical journal before applying snapshot-plus-tail, so it does not accelerate startup.

The journal v3/session and edit semantics currently use deterministic software fixtures. They preserve session epochs without selecting or merging a capture source and do not establish CT430 fidelity.

## M3 minimal canvas

The current M3 canvas renders committed, journal-projected Direct `WM_POINTER`/`GetPointerPenInfoHistory` pen strokes using GDI. This follows the owner-verified lock for the tested setup: Direct WM_POINTER with Windows Ink ON. `--capture-mode wintab` remains a separate diagnostic mode and does not draw through Wintab or fall back to another source. Public Winit events remain diagnostic only. New direct strokes append `StrokeStarted`, immutable raw sample rows, then a visibility commit only after a native `WM_POINTERUP`. Leave, capture loss, focus loss, device change, contact loss without an observed up, or shutdown appends an interruption; raw rows remain in the project journal and the incomplete stroke is not rendered as a completed stroke.

Project capture and edits go through a bounded worker queue. Each accepted journal append is synchronized before the UI receives its durable acknowledgement. Queue saturation stops further input, retains one pending batch for retry, and reports incomplete state; if shutdown cannot enqueue that batch, the project-finalization record reports its omitted event and sample counts. The project journal remains append-only and is stored under ignored `local_capture/` by default. `--project-path PATH` creates a project, while `--open-project PATH` appends a fresh session/arrival-clock epoch to an existing schema-v3 project. Legacy schema-1/2 inputs are migrated to a sibling schema-v3 file without rewriting the selected source.

The canvas shows pending strokes before the writer acknowledgement, keeps the preview while one bounded batch is pending, promotes it only after the durable visibility commit, and removes it on interruption or write failure. Each typed stroke-start row stores the observed `ClientToScreen` client origin and the DPI, pan, zoom, and toolbar frame for that stroke. Replay maps unchanged raw screen-pixel positions through the captured per-stroke frame, not the current window location. Window movement, DPI changes, and pan/zoom changes interrupt active contact; another stroke requires a fresh native down after lift.

Canvas controls: F1 selects the Direct pen tool; mouse drawing remains disabled. Use Windows Ink ON for the owner-tested pen-input setup. Ink OFF may remove Direct `PT_PEN` history; public mouse events remain diagnostic and are not promoted to ink. F2 selects the eraser; direct PT_PEN contact erases hit strokes on a proven native up, while mouse users click a rendered stroke and press Delete. F3 selects; pen or mouse can select existing strokes, then drag one selected stroke or use an arrow key to append a move. Direct eraser/select observations stay as raw physical rows without creating visible strokes. Ctrl+Z and Ctrl+Y append undo/redo controls; F5/F6 provide the same actions. Use the wheel to zoom and middle/right drag to pan. F4 or Enter shows that Convert is not implemented/configured in this build. These controls edit logical journal state; they never rewrite physical sample rows.

M4 defines a versioned JSON process protocol for capability discovery and recognition requests/results, carried over bounded local standard-input/output frames. Requests retain the exact journal boundary, region/line, language hints, source-ordered session-scoped StrokeRefs, raw units, and per-stroke view frames. Each request explicitly declares the required input modalities and each result echoes the modalities consumed; stroke samples remain canonical provenance for raster-only calls. Raster payloads are bounded opaque bytes with declared dimensions, not decoded pixels. The input-view ID covers the shared selected input and captured view, including modality choice, and is independent of provider configuration; configuration has a separate fingerprint echoed by handshake/results. Raw sample positions remain separate from projected positions after logical edits. Handshake, request, result, and stderr sizes are capped; worker I/O and shutdown have deadlines. Windows provider launch uses an atomic Job Object assignment with kill-on-close and explicit stdio-handle inheritance on Windows 10 or newer; setup failures stop the request without uncontained fallback. A crash, timeout, or stale result returns an error without dropping ink or switching providers. Result scores remain provider-native and uncalibrated. Starting a worker requires an explicit operator-approved absolute executable/configuration, separate from project metadata. The core has zero configured providers by default, no provider executable is shipped, and Convert remains unavailable. The CI mock worker is test-only.

After the direct provider exits, the runner releases its process handle and retains the Job Object while querying `ActiveProcesses`, reissuing termination while the count is positive. It joins the stdio helpers before closing the job; query, termination, or deadline failures retain resources in the bounded poisoned cleanup registry and block further provider work until the tree is reaped.

In-memory pending records are bounded by the existing 4,096-record and 131,072-native-sample caps. A direct native history is capped at 65,536 samples; one Wintab message drain is capped at 4,096 packets. When any capture or session-output limit is reached, capture stops and the window reports incomplete state. Invalid direct rows remain in the raw session, while valid-direct-pen row counts and pressure/interval metrics require `PT_PEN`, matching requested pointer ID, a reported pressure mask, and pressure in the inclusive 0 through 1024 range. Validation anomaly counts are separate from raw row counts. Wintab rows interrupted by a control notification, context/queue quality issue, or invalid packet status stay raw and are excluded from confident Wintab pressure metrics. Raw overlaps and duplicate fingerprints are retained; no sample rows are removed. Repeated direct fingerprints are counted but skipped in direct QPC interval and pressure distributions with an explicit exclusion reason.

`POINTER_INFO.PerformanceCount` and a QPC observation sampled at the Win32 hook boundary use the same QPC count domain, so the report may compute a message-receipt-to-hook-observation age and raw QPC intervals when frequency and values are available. P50/P95/P99 use the discrete nearest-rank rule `ceil(n*p/100)` within each qualified partition, with rank 1 as the minimum. These are not physical sensing-to-display latency measures. `dwTime`, Wintab `pkTime` (with mode), Winit public timestamps, and app `Instant` arrival remain separate. Missing/negative QPC values are reported as null with a reason. Derived metrics are partitioned by API, device, pointer, observed stroke, native clock, and pressure representation. Direct pressure histograms and entropy use valid unique raw pressure values only; repeat-run summaries are limited to valid unique direct rows within an observed stroke. Public Winit Force remains its own exact representation, partitioned by the recorded pen-classification state. Wintab `NORMAL_PRESSURE` remains uncalibrated raw u32 with unknown driver range and is never normalized or compared with direct pressure. No 220 Hz threshold or automatic frame-lock conclusion is applied. Focus loss, device lifecycle, pointer enter/re-entry/leave/capture loss, and device-range changes invalidate affected active stroke buckets; missing boundaries stay unclassified. The report never bridges clocks or strokes, joins public events to individual direct samples, interprets `frameId` gaps as proven loss, or claims hardware fidelity.

Process CPU is sampled with `GetProcessTimes` at app-arrival boundaries. Raw user/kernel FILETIME words and the measurement interval are retained. Its core-equivalent ratio covers the whole process and all its threads, includes the event loop and local session I/O, can exceed 100%, and is not an isolated capture-thread or driver cost. Positional jitter is unresolved because this probe has no calibrated noise measurement. Physical end-to-end latency is unresolved because there is no trusted clock bridge to an instrumented display endpoint.

The timeline includes direct pointer enter/leave/capture/device messages; Wintab packet/proximity and control/error messages; Winit focus and input-device add/remove; and event-loop wake delays over the declared diagnostic threshold. `--controlled-stall-ms N` arms a one-shot pause; press F9 once after the capture window is running to record app-arrival start/end markers and measured duration around a deliberate UI-thread pause (1..30000 ms). It never pauses automatically during startup and synthesizes no samples. Windows Ink, tablet profile, driver version, active area, display mapping, and pressure curve are owner declarations. The explicitly requested `--capture-mode direct|wintab` is independent of Windows Ink; the owner runner reads the Windows build from the current-version registry and records its source. The tool does not change system or driver settings. Live title refreshes remain limited to once per second.

In direct mode, the window reports `CAPTURE UNAVAILABLE` if the required Win32 pointer APIs cannot be loaded. A missing QPC frequency appears as a timing warning and does not prevent position capture.

Gate 0 is **PROVISIONAL PASS** for the owner-locked Direct WM_POINTER + Windows Ink ON capture contract in the tested setup. Diagnostic runs in other environments do not automatically requalify or change that contract. Criterion 8 remains partial for CPU cost of the capture callback/history query and true physical pen-to-display latency; this debt is explicitly nonblocking for the current implementation. This does not establish arbitrary CT430 driver, firmware, active-area, display-mapping, or pressure-curve defaults. Gate 1 recognizer-provider selection is separate, remains unpassed, and has no selected provider winner or official primary. Hardware-independent M2 journal and replay work may proceed using software fixtures; those fixtures prove only the software behavior exercised, not CT430 fidelity or an adapter choice.

## M5/M6 local benchmark preparation

Each `PROVIDERS.json` entry may optionally declare `requested_input_modalities`. When absent, the request inherits the case's legacy modality vector exactly and keeps the legacy raster-consistency rule: the case must include `Raster` if raster data is present, and must provide raster data if its case vector requests `Raster`. An explicit override for one provider does not relax this rule for another provider that omits the override. An explicit provider may select a nonempty, unique, capped set of modalities backed by case data. Provider capabilities are validated against that request; a mismatch fails visibly and never substitutes or retries in another mode.

M5 run rows carry a versioned `canonical_ink_comparison_binding` for the common canonical input. Its SHA-256 covers journal identity/logical revision, region/line and coordinate context, language hints, ordered stroke views/frames, and ordered source samples. It excludes provider configuration, requested modality, per-request `input_view_id`, and raster payload bytes. Each request still retains its own modality and `input_view_id`, which may differ across providers. `raster_pixel_parity` remains `unverified`; a shared journal binding does not prove that raster pixels match rendered pen input.

`--benchmark-batch CASES.json PROVIDERS.json [CORPUS-ANNOTATIONS.json]` runs a bounded serial batch through the existing local provider protocol. The case manifest pins an exact journal revision, region/line, selected session-scoped strokes, view units, language hints, requested modalities, and operator-declared trial provenance. Each provider configuration is supplied separately by the operator; every provider receives the same checked source revision, while each `input_view_id` remains specific to its request and may differ with requested modalities or raster input. Capability discovery, request/response validation, timeouts, process-tree cleanup, and no-fallback behavior remain those of M4.

Each supplied manifest file is a versioned JSON object with `schema_version: 1`. `CASES.json` contains `batch_id` and `cases`; each case supplies `case_id`, `journal_path`, `expected_source_revision` (`journal_id`, `logical_revision`, `last_sequence`), `region_id`, `line_id`, `coordinate_space`, `coordinate_units`, `language_hints`, `requested_input_modalities`, selected `StrokeRef` fields, and a `provenance` object (`writer_key`, `session_key`, `configuration_key`, optional `split`, corpus/annotation IDs, and declared capture settings). Corpus cases require an owner-declared UTC `session_start_unix_ns` and `capture_api_version`; the runner never invents session timestamps. Raster input is an optional explicit local binary file plus dimensions and coordinate units. `PROVIDERS.json` contains `providers` with `provider_id`, absolute `executable_path`, `arguments`, `protocol_configuration` (`configuration_id` and operator-supplied `values`), an explicit artifact list, and optional bounded handshake/recognition/shutdown deadlines. Exactly one artifact entry must identify the exact executable path for hashing; model/resource paths are hashed only when separately enumerated. The optional corpus file contains `corpus_id`, `split_key` (`writer`, `session`, `configuration`, or `session_start_time`), `bootstrap_cluster` (`writer` or `session`), a fixed `bootstrap_seed`, `bootstrap_replicates`, `tokenization_policy: "unicode_whitespace_syllable_v1"`, and one annotation per case with `annotation_id`, `reference_text`, and `reference_language_scope` (`vietnamese_only`, `mixed_or_unknown`, or `other_language`). `session_start_time` requires adaptation/calibration timestamps to precede future evaluation timestamps. Session IDs may not cross splits for any split policy. Optional delayed-mark annotations are checked against the selected sample sequence but are not scored without provider token-to-stroke alignment. Input paths must be local absolute non-UNC paths; symlink inputs are rejected.

`CASES.json` may set `repeat_count` to an integer from 1 through 5; omitted means 1. The runner rejects `case_count × provider_count × repeat_count` above 49,998 before any provider launch, leaving two of the 50,000 artifact rows for the header and footer. Repeats reuse the case's frozen journal state and raster bytes. Each transport request gets a distinct request ID, while the repeat-input identity binds the exact source revision, request view/modes, provider configuration fingerprint, and prelaunch artifact observations; a change makes that case/provider determinism result unavailable. Runtime-profile and required model-asset observations are also part of the execution identity. The footer compares only fully M5-eligible successful outputs with matching identities. Its SHA-256 digest covers only the ordered recognized-candidate projection: rank, `recognized_text`, native score, and stroke ranges. It excludes the provider-specific `raw_candidate` object, request/result identifiers, timing, and runtime diagnostics. The footer stores only opaque digests, counts, equality status, and bounded failure/unavailable reasons, not recognized text, reference text, paths, or configuration values. This records observed equality for those projected fields in those runs, not global determinism or quality. All private run rows and raw provider results remain in the local artifact.

Only predefined repeat index 0 contributes CER/WER, cursive/boundary summaries, or paired corpus comparisons. Later repeats retain their raw results but omit candidate quality metrics, so technical repeats do not create extra corpus/session observations or bootstrap samples. Provider runtime/timing summaries still describe attempted technical runs.

Each case may select one raster source: file-backed `raster` or `generated_raster`, never both. The generated source declares `projection_schema_version: 1`, output dimensions, and `source_crop` in canonical canvas pixels (left/top inclusive; right/bottom exclusive). The supported projection caps each dimension at 2,048 pixels, output area at 262,144 pixels / 1 MiB RGBA8, crop dimensions at 1,048,576 pixels, and crop area at 67,108,864 pixels. It projects only committed visible Direct WM_POINTER strokes with their captured per-stroke frames; missing/invalid frames are rejected without a session-origin fallback. Logical edits affect only derived geometry, while physical sample order and raw journal rows remain unchanged.

When at least one provider request selects Raster, the runner renders a declared generated source once from the already-verified journal revision and selected strokes, then reuses those PNG bytes for the raster requests. Generated PNGs over the provider's 1 MiB intake cap are rejected before launch, even though the renderer can produce up to 2 MiB; the runner never truncates, resizes, or changes modes as fallback. Generated-raster rows contain a metadata-only origin record tied to that request's shared canonical-ink binding, with source/spec/geometry/renderer/pixel/PNG hashes, dimensions, stride/layout, canonical draw order, and physical sequence provenance. PNG/pixel/sample bytes, local paths, and provider settings are not copied into that origin record. `raster_pixel_parity` remains `unverified`; derivation from the canonical journal view does not establish parity with an external raster image or model preprocessing.

An ignored, strictly guarded hosted mock E2E uses a synthetic committed Direct journal to cover online-only success, generated-Raster success, and a visible generated-Raster process failure without fallback. It decodes the generated PNG and checks request-specific input-view IDs, origin hashes/provenance, requested and consumed modes, raw response frames, footer counts, and artifact privacy. It does not exercise a real recognizer or establish image/model preprocessing parity.

The runner writes a JSON Lines artifact under `%LOCALAPPDATA%\LassoInk\benchmark` using create-new partial output and no-clobber final publication. The header stores SHA-256 digests of the exact case manifest and optional corpus/annotation manifest bytes; it never hashes the provider manifest because that file may contain credentials. Cases are processed one at a time; run records, file bytes, and record counts have explicit caps. Input, allocation, write, or cap failure leaves a visible `.partial` artifact. Provider failures are recorded as failed run rows; the footer's `complete` flag means every planned case/provider attempt has a row, not that every provider succeeded. Records keep exact source revision and input-view ID, region/line and coordinate units, language hints, ordered StrokeRefs/sequences, an optional raster byte count/hash, operator-supplied writer/session/configuration IDs (operators should use pseudonyms), declared capture settings, provider/configuration IDs and fingerprints, provider identity/capabilities, selected raw response frames, result candidates, phase timings, and raw Job Object measurements. Executable hashes are stored separately from model/tokenizer/resource hashes; if no model artifact is explicitly enumerated, the row records why model hashing is unavailable rather than treating an executable digest or self-reported model version as a model hash. The artifact does not copy operator provider settings, arguments, credentials, executable paths, raw request frames, input sample payloads, raster input bytes, or reference text. Provider response content is stored verbatim and may itself contain sensitive data; keep every artifact private/local. Only explicitly enumerated artifact paths from the separate operator configuration are SHA-256 hashed with fixed-size streaming and a size cap. That digest is a prelaunch observation, not authenticity proof or a guarantee against a file replacement race.

Text quality metrics are emitted only when the provider identity matches the fixed SenOCR reference and the row carries its frozen runtime-profile digest/catalog plus prelaunch SHA-256 observations for all 12 required model assets. Non-SenOCR or unbound providers, legacy rows without this evidence, and incomplete or mismatched SenOCR evidence remain diagnostic: metrics are withheld while raw provider results are retained. The profile and asset hashes are observations; they do not authenticate runtime wheels or files, or prove which bytes the provider loaded.

Human corpus annotations may include an optional `reference_handwriting_style` value: `print`, `semi_cursive`, `cursive`, or `mixed`; omitted/null values remain unknown. The runner records this annotation as metadata and never infers style from ink or provider text, sends it to a provider, or uses it in the request `input_view_id`. The footer reports style coverage and cursive-only CER separately within each declared split. Only references explicitly labeled `cursive` enter that subset; print, semi-cursive, mixed, and unknown references are excluded because no span-level eligibility contract exists. CER is micro-aggregated as summed edit errors over summed NFC Unicode-scalar reference units. Missing or zero-denominator observations produce null metrics and explicit reasons; partial coverage is identified instead of treating missing cases as zero errors.

The aligned orthographic-whitespace boundary metric is separate from the retained raw offset diagnostic. It NFC-normalizes Unicode scalars, collapses each interior run of Unicode whitespace into one boundary token, and uses a bounded Levenshtein alignment capped at 1,048,576 DP cells with fixed tie order: equal match, substitution, deletion, insertion. A matched boundary is TP; an inserted hypothesis boundary or scalar-to-boundary substitution is FP; a deleted reference boundary or boundary-to-scalar substitution is FN. It reports these counts and reference/hypothesis boundary totals, with micro error rate `(FP + FN) / reference_boundaries`, precision `TP / hypothesis_boundaries`, recall `TP / reference_boundaries`, and F1 `2TP / (2TP + FP + FN)` where denominators are available. Counts aggregate by provider/configuration/split before rates are computed; inserted boundaries are retained as false positives even on rows with no reference boundaries. Only the micro error rate is unclamped and may exceed 1; precision, recall, and F1 remain bounded by their count formulas. Zero denominators and over-budget alignments remain null with reasons. This scores orthographic-whitespace syllable/word boundaries, not lexical segmentation or text-to-stroke attachment.

Use the labels as follows: `print` means letters are mostly separately formed; `semi_cursive` means some connected or flowing joins appear, but writing is not predominantly connected; `cursive` means writing is predominantly connected or flowing; and `mixed` means materially different styles occur within one reference unit, so one label is inadequate. These are human annotations, not inferences from handwriting or provider output; mixed spans are not scored separately.

`elapsed_app_batch_call_wall_ns` measures the app-observed provider batch-call-start-to-outcome interval, including worker creation, admission, and poll overhead. Provider process phase durations use an app `Instant` sampled immediately before `CreateProcessW` and mark handshake, recognition response, parent exit, and Job Object tree drain. These are process wall durations; they are not sensor-to-display latency or a measured model-load phase. Model cold start is unavailable unless a future provider reports it. Job CPU is retained as raw `TotalUserTime` and `TotalKernelTime` 100-ns process-tree totals from job assignment through `ActiveProcesses == 0`; the optional core-equivalent percentage divides by CreateProcess-call-start-to-tree-drain wall time. The wall denominator starts just before the create call while job CPU accrues after atomic job assignment inside it, so it is conservatively wider and may understate the ratio. This describes the whole provider process tree and may exceed 100%; it is not capture-thread or driver CPU. `PeakJobMemoryUsed` and `PeakProcessMemoryUsed` are the raw Windows Job Object memory fields with their documented job/process scope; they are not labeled RSS or VRAM. GPU remains unavailable with a reason.

The footer includes bounded p50/p95/p99 system summaries per provider/configuration for app batch-call wall time, CreateProcess-call-to-handshake/recognition/tree-drain phases, whole-tree CPU ratio, and Windows peak-memory counters. It also includes model-cold-start and GPU null reasons, sample counts, and missing-observation counts. Percentiles use discrete nearest rank: `ceil(percentile * n / 100)`, clamped to the observed range. Failed attempts retain app batch-call wall time; unavailable process-phase, Job Object, and unsupported measurements stay null with run-level reasons.

An optional corpus annotation file enables software-only text evaluation. NFC Unicode-scalar CER uses edit distance on normalized scalar sequences. Vietnamese whitespace-token WER is labeled whitespace-token/syllable WER because spaces generally separate syllables/orthographic units, not necessarily lexical words. Lexical WER stays unavailable without a validated predicted word segmenter. NFD mark-inventory differences remain diagnostics. Vietnamese tone/modifier alignment runs only when the annotation explicitly declares the entire reference `vietnamese_only`; mixed/unknown text receives null mark metrics in schema v1 because Vietnamese span-level scoring is not implemented, while CER, syllable WER, and inventory diagnostics continue. The bounded NFD scalar alignment counts mark edits on a deterministic minimum-edit path with reference vowel-nucleus count as its denominator. Alignment ties prefer diagonal, deletion, then insertion; a substitution between a tone mark and a vowel modifier contributes to both category counts. Those edit counts are not calibrated language-error attribution. Whitespace syllable-boundary output is a raw cumulative-offset diagnostic, not aligned boundary accuracy. Delayed-mark attachment stays unavailable because the current provider protocol does not supply validated token-to-stroke alignment. Reports score each provider's rank-0 candidate without selecting a winning provider; raw candidate lists remain preserved. Paired comparisons resample writer or session clusters with a fixed seed and declared replicate count, within each declared split; each CER/WER comparison has its own paired-case and cluster counts, and intervals are unavailable below two independent clusters. A global cap of 10 million cluster-resampling draws withholds all intervals for an over-budget artifact while keeping paired counts and explicit reasons. Available intervals are nominal, unadjusted exploratory summaries; the artifact prohibits winner/significance claims and they are not selection evidence. Any Gate 1 provider selection requires a predeclared multiple-comparison correction. The split policy checks that its writer/session/configuration key does not cross splits and session-time mode requires adaptation/calibration plus all prior non-evaluation sessions to predate future evaluation. Empty denominators, edit-distance work caps, or missing alignment produce explicit nulls/reasons.

Case journals, corpus annotations, provider settings, provider outputs, and benchmark artifacts can contain private handwriting, credentials, or local installation details. Keep them in local-only paths and out of Git and public issues. The M5/M6 software fixtures use synthetic inputs and do not establish CT430 fidelity, provider accuracy, license rights, or a recognizer winner. The core app bundles no SDK/model/corpus assets; the separate opt-in hosted compatibility job downloads a pinned FP32 model only into runner temporary storage, uses a generated blank image, and uploads no model/input/output artifact. No Gate 1 selection or provider winner is established.

## Requirements and build

The project pins Rust 1.100.0 for `x86_64-pc-windows-msvc`. Install the pinned toolchain and target if they are not already present:

```powershell
rustup toolchain install 1.100.0 --profile minimal --component clippy --component rustfmt --target x86_64-pc-windows-msvc
```

Run the diagnostic or parse a finalized/partial session:

```powershell
cargo run
cargo run -- --capture-mode direct
cargo run -- --capture-mode wintab
cargo run -- --capture-mode direct --session-dir local_capture --trial-id ink-off-direct --windows-ink off --tablet-profile default
cargo run -- --capture-mode wintab --session-path local_capture\ink-off-wintab-osu.tsv --windows-ink off --tablet-profile osu
cargo run -- --controlled-stall-ms 2000 --capture-mode direct --trial-id controlled-stall
cargo run -- --report local_capture\session-file.tsv
cargo run -- --status
cargo run -- --version
cargo run -- --help
```

`--capture-mode` must be selected independently of `--windows-ink`. If the controlled stall is requested, press F9 once after the window is running; a configured duration alone never causes a startup pause.

The quality checks used by Windows CI are:

```powershell
cargo +1.100.0 fmt --all -- --check
cargo +1.100.0 clippy --locked --workspace --all-targets -- -D warnings
cargo +1.100.0 test --locked --workspace
cargo +1.100.0 build --locked --workspace
```

The default local test suite excludes native HWND, Winit event-loop, and GDI integration tests. They run only in a separate guarded GitHub-hosted Windows CI job after the default checks. The native tests require explicit opt-in, the GitHub-hosted Windows runner marker, and the `Herzchens/LassoInk` repository identity before they can call UI APIs.

## Data handling

M1 session files may contain sensitive handwriting, timing, pressure, and device data. Keep them in an ignored local path or the owner-selected local session directory. They are not uploaded. Do not put them in the owner package, Git, or a public issue. The owner runner defaults session files to `%LOCALAPPDATA%\LassoInk\capture-sessions`, outside the package directory.

## Dependencies

The app directly depends on Serde 1.0.229 with derives, Serde JSON 1.0.154 for the bounded local provider protocol, Winit 0.30.13 with default features disabled and the `rwh_06` interoperability feature, Windows-target `windows-sys` 0.52.0, `sha2` 0.11.0, and `unicode-normalization` 0.1.25. `Cargo.lock` records the resolved transitive packages including `raw-window-handle`.

## Optional hosted raster runtime compatibility check

The `raster-cpu-compatibility` job has a source-controlled explicit opt-in and runs only for a same-repository pull request from `feat/raster-reference-protocol` on a GitHub-hosted Windows x64 runner. Before checkout, dependency installation, or model access, it verifies the event, repository, runner, branch, explicit flags, and exact head SHA. It reuses the fixed 12-file full-precision SenOCR-Vi safetensors/config/tokenizer allowlist and the pinned Python 3.13.17, PyTorch 2.15.0 CPU, Transformers 5.23.0, Pillow 13.0.0, and Jinja2 3.1.6 runtime. The verified files stay in runner temporary storage and are removed after the test; the job uploads no model, input, generated text, or report artifact.

The guarded job also exercises the real M4 parent with a synthetic journal and canonical PNG, including the worker's decoded RGB and processor-input comparison against direct in-memory canonical pixels. This is a software path regression only: it does not requalify or change the owner-locked capture contract, establish recognition quality, external-raster or model-preprocessing parity, or hardware fidelity. The actual worker is optional and is not selected as the default provider. M4 does not enforce OS-level network isolation; the worker requests offline/local-only library loading. The recognition test uses the existing 120-second M4 call ceiling without changing provider timeout defaults. No production distribution, license, Gate 1, or provider-selection clearance is implied.

## Optional local Raster worker

The SenOCR-Vi worker accepts only an explicitly supplied local asset directory that matches its pinned file allowlist and hashes. Invoke the script by its absolute path from any working directory; it does not read executable paths or model locations from project metadata. The repository bundles no model assets, and normal app startup does not enable this worker. It returns the provider's raw text candidate without calibrated scores or stroke alignment. The guarded synthetic test does not validate handwriting quality, product eligibility, external raster parity, or OS-level network isolation.
